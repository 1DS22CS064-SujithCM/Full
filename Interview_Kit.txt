SRE AGENT:
The title of the project is **AI-Powered SRE Multi-Agent System**, an AI-based platform developed to automate the investigation of production alerts in GCP environments. The system uses **Python, FastAPI, PostgreSQL, React.js, and multiple AI agents**, with MCP used to interact with monitoring and infrastructure tools.
The main objective of the system is to help **Site Reliability Engineers** investigate production issues faster by automatically analyzing alerts, collecting relevant evidence, identifying possible root causes, and generating a structured Root Cause Analysis (RCA).
The flow of the project starts when a **production alert is received through a GCP alert webhook**. The FastAPI backend starts an investigation session and passes the alert to the **Coordinator Agent**, which manages the complete investigation process. The **Discovery Agent** then understands the alert, checks previous incidents and knowledge-base information, and performs the initial triage.
After that, the system creates **testable hypotheses** about what could have caused the issue. Three investigation lanes run in parallel, where each lane follows **Planner, Executor, Assessor, and Critic** stages. The Executor uses **MCP tools** to collect real-time information from Kubernetes, GCP Logs, Metrics, and other infrastructure systems, while the Assessor evaluates the quality of the collected evidence.
To improve accuracy, the system uses a **Shared Evidence Pool** so that different investigation lanes can share useful findings. A convergence mechanism checks whether enough reliable evidence has been collected and stops unnecessary investigation once the root cause becomes clear.
Finally, the **RCA Agent** uses the validated evidence to provide the **root cause, contributing factors, dependencies involved, supporting evidence, tools used during the investigation, and recommended remediation steps** to resolve and prevent the issue.

Project - 4
Thread-Mastery:
Good morning sir, the title of my project is ThreadMastery and it is developed using Java with the main objective of demonstrating different threading and concurrency models in a client-server environment and comparing their efficiency. The project has three modules: a single-threaded server where only one client is handled at a time, a multi-threaded server where each client gets its own thread allowing concurrent handling but with the drawback of high overhead under heavy load, and a thread pool server where the ExecutorService manages a fixed pool of worker threads to efficiently handle requests without creating excessive threads. In all three modules, the client sends a number and the server returns its factorial, using ServerSocket and Socket classes for networking and BufferedReader with PrintWriter streams for communication. Through this implementation, I was able to compare performance, scalability, and resource management across the models, and I observed that thread pooling is most efficient for real-world applications as it balances stability and system resources. Overall, this project gave me strong hands-on knowledge of Java networking, concurrency, and backend optimization.

Project - 6:
Serverless Web Application for Student Data Management:
The title of my project is “Serverless Web Application for Student Data Management.”
It is developed using HTML and JavaScript for the frontend and AWS Lambda with DynamoDB for the backend. The main goal is to create a fully serverless, scalable, and cost-efficient system to store and retrieve student details.

The project mainly uses DynamoDB, Lambda functions, and API Gateway.
In DynamoDB, we created a table StudentData with the student name as the partition key.

For backend logic, we built two Lambda functions:
getStudents – fetches all student records
insertStudentData – inserts new student data
Both are written in Python 3.12 and connected to API Gateway using GET and POST methods. The generated API endpoint is added in the JavaScript file, and CORS is enabled for browser access.
The frontend (index.html and scripts.js) is hosted in an S3 bucket with static hosting enabled. To improve security and speed, CloudFront is placed in front of the S3 bucket for HTTPS and global caching.
Overall, the project shows how to build a complete serverless application without managing servers, ensuring low cost, high scalability, and easy maintenance.

Hackathon Description:
In our college hackathon, the problem was that many patients forget their follow-up appointments, which leads to delays in treatment and extra work for
hospital staff. Our solution was designed for Jayadev Hospital to make follow-up management easy. When a patient visits for the first time, the receptionist records their details, a short description of their condition, and the next visit date in the system. One day before the follow-up, the system automatically sends an SMS reminder to the patient. The message also contains a link where they can check the exact time of their appointment. This solution not only reduces missed appointments but also saves staff time by automating reminders, making patient care more efficient and reliable.

how do u send message:
To send SMS reminders, we used an SMS gateway API service like Textlocal The hospital system triggers the API one day before the scheduled appointment. The API takes the patient's phone number and the reminder message as input and delivers the SMS instantly. This approach is reliable, works with any mobile network.
